# Port notes

numpy and scipy semantics a port must reproduce, collected by the agents that wrote the golden cases while
reading the code (one list per group, from the last report of each). Each line names a behavior; the matching
case `doc` says where it bites. Treat a line as a lead to check against the case, not as a proof.

## sphere_noise

- np.floor(x).astype(np.int64) then & 255 / & 1023: negative cells wrap by two's complement masking (-1 & 255 = 255); in Rust use (x.floor() as i64) & 255, never a truncating cast of x and never % on a negative.
- sample_equirect: x0 % w uses numpy floor-modulo (result in [0, w) for negative x0); Rust % keeps the dividend's sign, so use rem_euclid. Latitude indices are np.clip'd (no wrap) while longitude wraps; fx = (lon + pi) / (2 pi) * w - 0.5 and fy = (pi/2 - lat) / pi * h - 0.5 put texel centers at integer coordinates.
- sample_equirect with float32 directions: lon, lat, fx, fy are float32, but fx - x0 mixes float32 with an int64 array and is promoted to float64, so weights and output are float64 (a float32 image times float64 weights gives float64).
- np.arctan2 is IEEE atan2 with signed zeros: atan2(+0, -1) = +pi, atan2(-0, -1) = -pi, atan2(0, 0) = 0; WGSL does not guarantee the signed-zero behavior (case dir_to_lonlat.signed_zero is tagged degenerate). np.clip(z, -1, 1) before arcsin keeps |z| > 1 from giving NaN; a NaN z stays NaN.
- dtype follows the input: lonlat_to_dir and dir_to_lonlat on float32 arrays compute their trigonometry in float32 (float32 pi/2 is 1.5707964 > pi/2, so cos = -4.4e-8 at the 'pole'); grid_dirs always computes in float64 and rounds to the requested dtype once.
- normalize is v / np.linalg.norm(v, axis=-1, keepdims=True): the sum of squares in the input dtype (float32 stays float32), unguarded: zero vector gives NaN, squares that overflow give 0 or inf (no hypot, no scaling). Cases normalize.degenerate.* are tagged degenerate: a guarded port may differ.
- tangent_frame: np.cross(z, c) promotes a float32 center to float64; the pole guard is norm < 1e-9 on |z x c| = hypot(cx, cy), pinned within 1e-4 relative by tangent_frame.threshold_bracket; the fallback east is (0, 1, 0) and north = c x east is NOT renormalized (it has the length of c).
- gnomonic_patch: np.linspace(-1, 1, 1) is [-1.0] (not 0), so n = 1 gives the north-west corner; linspace end points are exact +-1; np.meshgrid(t, -t) default 'xy' indexing puts row 0 at +tan (north) and column 0 at -tan (west).
- upsample_dirs must build the target grid in float64 (grid_dirs(width, height, float64)), convert the coarse grid to float64, blend the 3-D vectors, renormalize in float64 and round to float32 ONCE at the end; a float32 target grid misses by 5e-4 on a 512-row coarse grid (arcsin ill-conditioning just outside the pole clamp, case upsample_dirs.tall_poles.*). The band loop (1 << 22) // width rows changes nothing: rows are independent.
- np.round / rounding is not used by these modules; float32 rounding happens at astype(np.float32) (round-to-nearest-even). Python float constants (6.0, 15.0, 0.5) do not promote float32 arrays (NEP 50 / weak scalars), so _fade and the Perlin lerps stay float32 on float32 input and float64 on float64 input.
- Perlin3 and Worley3 read DOUBLED permutation tables, concat(perm, perm): 512 entries (p[A + 1], p[AA + 1] reach index 511) for Perlin3, 2048 for Worley3. The stored plan<i>.perm is the single 256- or 1024-entry draw; every case with one carries params.perm_doubled = true.
- _grad: h &= 15; u = x if h < 8 else y; v = y if h < 4, x if h is 12 or 14, else z; bit 0 of h negates u, bit 1 negates v (np.where(h & 1, ...) treats any nonzero as true). The lerp is a + t * (b - a) in that operation order (a*(1-t) + b*t differs by 1 float32 ulp, measured 1.9e-7).
- fbm accumulates per point in octave order in float32: q = (pts @ rot.T) * float32(freq) + off, v = float32 noise, billow v = |v| - float32(mean1), total += float32(amp) * v, result = total * float32(norm); amp, freq and norm are computed in float64 and rounded to float32 per use. pts @ rot.T is a float32 BLAS matmul: summation order and FMA use are unspecified.
- Chunking: fbm and cell_edges evaluate in chunks of 1 << 20 points; a port may chunk differently. Float32 summation order inside a point does not depend on the chunk, but BLAS may pick another kernel for a one-row remainder chunk and move float32 results by the chain error (observed 2e-4 for fbm billow at frequency 400 with a remainder of 1); the case tolerances cover that, bit identity is not guaranteed.
- _random_rotation: q, r = QR(g); q *= sign(diag(r)) makes the factorization unique (any QR algorithm gives the same q); then column 0 is negated when det(q) < 0 so det = +1. np.sign(0) = 0 would zero a column (never happens for normal draws); the rotation is scale free in g.
- Worley3 takes floor() and the fraction in the dtype of the points (float64 stays float64) and only then rounds the fraction to float32; rounding the points first costs up to 8e-5 at |x| ~ 2000 (case worley3.f64_points.large). Ties: f2 = where(d2 < f1, f1, minimum(f2, d2)) before f1 = minimum(f1, d2), so an exactly equal distance becomes F2 == F1. All distances are float32 squares, sqrt at the end; the cell hash is perm[perm[perm[X] + Y] + Z] with the doubled table.
- cell_edges: q = (flat @ rot.T) * float32(frequency) (matmul first, then the scale), F2 - F1 in float32; frequency 0 gives one constant for the whole array; a negative frequency mirrors the points.
- octaves_below compares frequency * lacunarity ** n with Python float pow (libm); repeated multiplication or powi can round the other way exactly on a boundary (case octaves_below.fragile). octave_ladder computes int(np.floor(np.log(hi / low) / np.log(lacunarity))) + 1, so a ratio that is an exact power of the lacunarity lands on either side by log rounding (case octave_ladder.fragile, tagged fragile).
- Defaults the callers rely on, pinned by the .defaults cases (arguments omitted from the inputs, listed in params.omitted_arguments): octaves_below lacunarity 2.03; octave_ladder lacunarity 2.03 and top 0.95; map_max_frequency min_texels 4.0.
- fbm statistics (slow cases fbm.stat.*): a port draws its own tables, so only the mean and standard deviation over 200000 points are compared, each within 4 sigma of params.expect; PERLIN3_STD 0.2692 and PERLIN3_ABS_MEAN/STD 0.2171/0.1542 are module constants the port reads from the source (billow mean is about 1.5% above 0 on unit-sphere points).
- Tags: slow and stat as in the README; degenerate (unguarded NaN/inf or signed-zero behavior) and fragile (floor boundary decided by the math library) mean a port may skip or relax the case; the function prefix property. (random_rotation.recorded_orthonormal) marks a case that is a property of recorded data, not a call of a function.

## climate_flow

- Python max(a, b) returns a unless b > a: max(0.0, NaN) = 0.0 and max(1e-3, NaN) = 1e-3. Rust f64::max also ignores a NaN operand and matches; f64::clamp propagates NaN and does not. np.clip propagates NaN.
- hadley_edge_raw_deg: a None, NaN, +-inf, 0 or -0.0 rotation period gives +inf; the period enters only through abs(EARTH_ROTATION_DAYS / p), so its sign is lost (only build_flow reads it, through math.copysign(1.0, period)). A NaN gravity or scale-height product becomes 0 through max(0.0, g H), so the raw edge is 0 (a fast rotator); a NaN radius gives a NaN raw edge.
- hadley_edge_deg tests math.isfinite(raw) (NaN and -inf also give 90.0), then min(90, max(10, raw)). A negative radius gives a negative raw edge, which clamps to 10.
- Keep the operation order raw = 30 * sqrt(gh_ratio) / (omega_ratio * radius_ratio): it is IEEE-exact and makes the body with period 1.6621166666666667 d (Earth radius, g and H) give exactly 50.0, where has_baroclinic_eddies must be false (strict <). Its one-ulp neighbors give 49.99999999999999 (true) and 50.000000000000014 (false).
- map_width_for_texel: w = ((2 pi) radius) / texel is a true division, then 2 ** ceil(log2(max(w, 2.0))) with libm log2. At w exactly one ulp above 2^k, math.log2 returns k exactly and the width is 2^k (the oracle), not 2^(k+1): call f64::log2 and ceil, never an integer test. Widths 1e-14 to 1e-11 relative above 2^k give 2^(k+1). The cap is returned as is, even when it is 0, 1 or not a power of two. 2 ** ceil(...) is a Python big int and overflows u64 above 2^64, so compare in floating point or saturate before shifting.
- math.radians and np.radians multiply by (pi / 180) and degrees by (180 / pi), the same constants as Rust to_radians and to_degrees. Use them rather than x * pi / 180, which differs in the last bit and shows in the exact-50 body and the 1e-9 pole test.
- NumPy 2 (NEP 50) promotion decides the dtype chain: a Python float is weak, an np.float64 scalar is not. zonal_rate(float32 lat) subtracts the np.float64 scalar prof(1.7) and returns FLOAT64 holding float32-rounded values. target_zonal_coverage(float32 lat) gives a float64 output (x and the two smoothsteps float32, the shift fade and ITCZ gaussian float64 through np.asarray(float64)). convective_tendency(float32) stays float32. Every flow and climate case stores this in params.dtype_chain.
- target_zonal_coverage: itcz_shift_deg is a Python float and stays float64. Rounding it to float32 moves the output by up to 1.1e-8 (shift_not_float32 case, 2.7 to 38 times its tolerance band). The floor max(1e-3, hadley) appears three times (x, the shift fade 0.5 max(1e-3, h), x_itcz).
- np.exp underflows to 0 and overflows to inf silently; (x - mu) / sigma squared can overflow to inf, so exp(-inf) = 0. np.clip(c, 0, 1) propagates NaN; the 0 lower bound is never taken.
- Flow.velocity and Flow.ascent in float32: the vortex center is the float64 lonlat_to_dir(lon, lat) = (cos lat cos lon, cos lat sin lon, sin lat) cast to float32; d2 = np.sum((p - c) ** 2, axis=1) adds x + y + z left to right (3 elements, no pairwise tree); np.cross(z, p) = (-p_y, p_x, 0); exp and the weights are float32; v += and a += accumulate in vortex order (another order changes float32 rounding).
- Flow.velocity latitude is arcsin(clip(p_z, -1, 1)), so a non-unit p with |z| above 1 acts as a pole; the Gaussian distance and cross product use the raw, unnormalized p. |lat| makes zonal_rate symmetric about the equator, and it accepts latitudes beyond +-pi/2.
- Flow.backtrace integrates in float64 whatever the input dtype: q = p.astype(float64); mid = normalize(q - 0.5 dt v(q)); q = normalize(q - dt v(mid)); dt = time / steps; only the returned array is cast to float32 (round to nearest even). sphere.normalize is v / np.linalg.norm(v, axis=-1) with no epsilon: a zero vector gives NaN. time = 0 only renormalizes; a negative time advects forward.
- Flow.ascent: a cyclone computes its plain Gaussian and then overwrites it with _comma_ascent (the first one is dead). A tropical eye uses the VORTEX radius (eye = 0.12 radius), not the 0.6 radius of the ring. float64 input: per-vortex math in float64, each term cast to float32 before accumulation; float32 input: everything float32. The term is np.float32(ascent) * g.astype(float32).
- _comma_ascent: east = cross(z, c) in float64; if |east| < 1e-9 (strict, pinned to 1e-5 relative) east is (0, 1, 0). pole = cross(c, east) * math.copysign(1.0, lat): copysign reads the SIGN BIT, so lat = +0.0 gives +1 and lat = -0.0 gives -1 (do not test lat >= 0). grown = min(age, 1); head = normalize(c + radius * shift) cast to p.dtype; the dry slot (age - 1) * 2 exp(...) is subtracted only for age > 1.
- build_flow: Python round(x) is round-half-to-even (Rust f64::round is half away from zero: use round_ties_even), m = max(2, round(2 pi cos(track) / (5 L_R))), 5.0 is pinned to 0.005 per cent by the wave_<k>p5 bodies. A body without a storm track returns early with (jet, trades, polar_easterlies) = (0.3, 0.1, 0.0), hadley_deg from hadley_edge_deg, and no vortices, before copysign sees a None period.
- build_flow draws with numpy default_rng(seed ^ 0x5F10) (PCG64, any integer seed, including above 2^32): per hemisphere lon0, then per low i the longitude jitter, latitude, age, radius factor, omega factor, then the high's longitude factor, latitude, radius, omega, then poisson(1.5) tropical storms (latitude, longitude, radius, omega). A port with another generator cannot match these numbers; it must pass build_flow.structure.bodies exactly and the stat cases statistically. Vortex longitudes are not wrapped: lon0 + (i + jitter) 2 pi / m. spin = copysign(1.0, period) flips every omega but not the latitudes.
- The 1e-9 pole test and the half-integer rounding of m both depend on the last bit of libm sin and cos: the cases keep 1e-5 relative (pole) and 5e-5 relative (wave count) away from them, and a latitude near pi/2 is quantized by 2.2e-16, i.e. 2.2e-7 relative at 1e-9.
- JSON carries no NaN or infinity in params. A rotation period of None is stored as NaN in the input arrays, and non-finite values appear only in input and output arrays (36 listed arrays), compared with NaN equal to NaN and an infinity equal to the same infinity.

## texture_surface

- np.degrees(x) is x * (180 / pi) (Rust to_degrees is the same single multiplication); grid_lonlat is lon = -pi + (i + 0.5) * (2 pi / W), lat = pi / 2 - (i + 0.5) * (pi / H): keep this operation order, the earth_tables band-edge ties (row_x output, compared exactly) depend on the last bit.
- Python float arguments are WEAK scalars (numpy >= 2 promotion): _smoothstep / _gauss on a float32 array run entirely in float32 and return float32; on float64 they stay float64. np.degrees of a float32 array stays float32 (regime_weights mixed-dtype case).
- _standardize uses float32 mean and float32 std (ddof = 0) with numpy pairwise summation when the input is float32; a CONSTANT float32 field such as 0.1 has a nonzero float32 std (7.45e-9 for n = 7 or 64, exactly 0 for n = 8 or 16) and standardizes to -1, not 0; only dyadic constants (0, 0.5) give std 0 and the 'divide by 1' fallback (`sd > 0`, strict, no epsilon).
- regime_weights: the normalization is `total > 1.0` strict (>= is equivalent), scale = 1 / max(total, 1e-9); np.where evaluates both branches; closed, open and street keep the dtype of their inputs; convective_tendency (climate group) is part of the formula.
- regime_texture: f = radius_km / d_km must be a DIVISION (a multiply by a reciprocal can move a tie one ulp); `f > fmax` is strict, so f == fmax is USED; cell seeds are seed + int(d_km); the closed and open accumulators are float32 with np.float32(weight); each of the four fields is standardized over the WHOLE array with a global mean and std.
- Surface.from_elevation casts elevation to float32 FIRST, then subtracts np.float32(sea_level) in float32 (a float64 subtraction would call float32(0.3) land at sea level 0.3); land = e > 0 strict; elevation = max(e, 0).
- Surface.load: land = u8 / 255.0 and elevation = max(int16 / 1000.0, 0), both float32 divisions (weak python scalar), int16 is little-endian; source defaults to the land file NAME, not the path; the case stores it as the UTF-8 bytes output source_utf8.
- Surface.at: the box branch needs w % width == 0 AND h % (width // 2) == 0 (both tests), the box mean is a float32 mean over f x f blocks; otherwise sample_equirect (bilinear, longitude wraps, latitude clamps, computed in float64 and cast to float32, no prefiltering, so down-sampling aliases); same width returns the object itself.
- smooth_on_sphere: scipy gaussian_filter1d with truncate = 4.0: radius = int(4 s + 0.5), weights exp(-0.5 x^2 / s^2) normalized to sum 1, accumulated in float64, output float32; mode 'wrap' is periodic even when the radius exceeds the length; mode 'nearest' repeats the edge; the row pass is skipped (row copied) when s <= 0.3 px (strict `s > 0.3` filters), s = min(w / 4, sigma_km / (px_km max(cos lat, 1e-3))), px_km = 2 pi R / w; the column pass uses sigma_km / px_km with axis = 0.
- deck_strength: the coast test is cont >= 0.5 on the float32 values (0.5 is a coast, nextafter(0.5, 0) is not); the search uses np.searchsorted(ext, idx) with side = 'left' (a coast at the cell itself has distance 0), ext = concatenate(c, c + w) for the wrap; dist * dx > 4000 (strict) is infinite; spin >= 0 is prograde (0 counts as +1), spin < 0 mirrors the row before and after; exp is float64 rounded to float32, then a float32 product with (1 - cont); rows with no coast or all coast are zeros.
- earth_tables: the band test is the half-open x >= a and x < b on float64 x = |degrees(lat)| / hadley against k / 6.0; an empty band is NaN (mean of an empty slice), a row with x >= 15/6 is in no band; both hemispheres share bands; field means are float32 means.
- np.interp clamps outside the table (no extrapolation) and keeps the input shape (earth_tables_at on a (rows, 1) column returns (rows, 1)).
- hemispheric_land_asymmetry: rows are float32 means; `lat > 0` and `lat < 0` exclude the equator row of an odd-height grid; the weights are cos(lat) in float64; the result is a Python float.
- itcz_shift_deg: np.clip of the x shift to +-ITCZ_SHIFT_MAX_X before multiplying by hadley_deg; None gives exactly 0.0.
- orographic_anomaly: np.roll(+-1, axis = 1) gives the periodic centered difference in longitude; dh/dy is zero at the two pole rows (only rows 1..h-2 are filled, row - 1 is north); three floors: dx_km uses max(cos lat, 1e-3), the speed is max(hypot(u, v), 1e-3), the back-trace longitude divides by max(cos lat, 1e-3); the floors only bind on grids above 1570 rows (cos) or below 1 mm/s (speed), and the cases pin each of them.
- orographic_anomaly shadow: the upwind direction can leave the sphere (la2 > 90 deg: cos(la2) < 0), which sample_equirect maps to the far meridian through arctan2 / arcsin of the unit vector; lookups take the maximum over the four fractions 0.15, 0.35, 0.6, 1.0 of RAIN_SHADOW_KM, weighted by (1 - 0.5 frac); tanh and the sampling are float64 rounded to float32 at the end.
- float32 versus float64 promotion: surface_terms and the orographic chain mix float32 arrays with float64 grids (dx_km, lat); numpy promotes the product to float64, and only lift, up and the final anomaly are stored as float32; a port that keeps float32 end to end differs by about 1e-7 absolute, well inside the stored tolerances.
- Summation order: np.mean over float32 arrays (field means of earth_tables, row means of hemispheric_land_asymmetry, block means of Surface.at) are pairwise float32 sums; a float64 accumulation differs by up to 6e-8 relative, inside the tolerances (1e-5 / 1e-6, 1e-6 / 1e-7 for the asymmetry).
- A string result cannot be an output array: Surface.load's `source` is stored as UTF-8 bytes in the output source_utf8 (and in params.expected_source).

## products_generate

- np.round is round-half-to-even (encode_wind: 128.5 -> 128, 129.5 -> 130); Rust f32::round is half away from zero, use round_ties_even. np.rint is the same, so mutant 'round -> rint' is equivalent.
- encode_wind evaluates 128 + wind / 0.5 in the dtype of wind: a float32 input rounds the sum to float32 (spacing 1.5e-5 near 128), so a value a few 1e-6 above a .5 tie is absorbed into the tie and rounds to even, while float64 would round it up (encode_wind.near_ties.f32 vs .f64 differ). Order is round, then clip to [0, 255], then astype(uint8); +-inf and +-3e38 saturate, NaN is excluded (undefined).
- np.clip passes NaN through and np.clip(+inf) gives the upper bound; Rust f64::clamp also propagates NaN but x.max(lo).min(hi) swallows it. Use clamp (compose and _smoothstep rely on NaN surviving only in degenerate cases).
- np.interp clamps outside the table (left and right default to the end values): high_share at x = |lat| / hadley > 3 returns 0.2; the table x must be increasing.
- numpy promotion: a python float is weak (float32 array op python float stays float32), float32 array op float64 array gives float64. In compose, u = s - t is float32 for a python-float t and float64 for a float64 threshold column; 1 + a_fine * fine and 0.5 + 0.5 * streak are rounded to float32 first when fine and streak are float32. The result dtype follows (params.result_dtype).
- area_mean averages each float32 row in float32 (numpy pairwise summation) and then weights in float64 with cos of the cell-centre latitudes; a float64 port differs by about 1e-8 relative.
- solve_thresholds: 36 steps on [-10, 10], returns the midpoint of the final bracket (width 20 / 2^36 = 2.9e-10, a dyadic number); the decision is the strict mean > target (a row of exactly 1.0 at target 1.0 never triggers, so the result runs to the lower bound); the row mean is a float32 or float64 pairwise sum depending on compose's dtype; np.where picks lo or hi per row.
- row_sensitivity is (lo - hi) / (2 e) with the floor np.maximum(., 0.05) applied after the division; saturated rows return exactly 0.05.
- compose: shield = clip(0.5 + u / ramp, 0, 1) overflows to +-inf at u = +-3e38 and is clipped to exactly 0 or 1; sqrt(c (1 - c)) is safe because c is clipped to [0, 1] first; at a saturated texel the binomial term is exactly 0 so coverage is exactly 1 or 0.
- surface_regime_weights: sea = 1 - continentality and closed = w_closed * sea are float32; (1.0 - closed) is rounded to float32 BEFORE it meets the float64 deck = deck_window(x) * deck_strength, then closed is float64; scale = where(rest > 1e-9, min(1, (1 - closed) / max(rest, 1e-9)), 1) is not clamped below, so shares of -2.3e-8 occur; np.where evaluates both arms; results are cast with astype(float32) (round to nearest even). Where 1 - closed is under a float32 ulp (deck columns of tiny_rest) a float32 closed gives 0 or 6e-8 and is wrong.
- type_map and high_share cast their result with astype(float32) after the clip; type_map's (1 - wc - wo - ws) is float32 for float32 weights. np.degrees on float32 latitudes (moisture_profile) stays float32.
- zonal_wind_scale and climatological_zonal_mps: `period or 1.0` treats both None and 0.0 as +1 (so the spin is +1 there, and the profile is +0); -0.0 is falsy too; math.copysign(1.0, period) gives -1 for any negative period including -243; has_baroclinic_eddies is the strict raw edge < 50.0 and the raw edge is infinite for None, 0, +-inf and NaN (no storm track, scale exactly 0); gh = max(0.0, g * H) is floored before dividing.
- wind_map: height = width // 2 (floor, odd widths allowed, width 2 gives one row at latitude 0); everything is float64 (grid_dirs with dtype float64) and the result is cast to float32 once at the end; the climatological zonal wind is symmetric in |lat|, so flipping the rows changes nothing; Flow's own jet, trades and polar_easterlies are ignored (a still Flow with 0 for all three is built).
- _smoothstep with a == b divides by zero: -inf and +inf clip to 0 and 1, and x == a gives 0 / 0 = NaN which np.clip keeps; sphere.normalize divides by the norm with no epsilon, so a zero vector gives NaN (along.antipodal_nan).

## pipeline

- np.round is round-half-to-even: use f32::round_ties_even (Rust f32::round is half-away). Ties are exact here: (k+0.5)/255 * 255 == k+0.5 in float32 and float64 (127.5 -> 128, 126.5 -> 126), and c * 65535 likewise.
- A float32 array times a Python int or float stays float32 (NEP 50): c * 255, c * 254, c * 65535, 128.0 + wind / 0.5 are computed in the input dtype; a float64 input gives float64 arithmetic. np.clip comes first, so +-inf and out-of-range values are clamped; astype(uint8/uint16) follows round.
- write_entry's slice has NO clip (np.round(box_downsample(cov, SLICE_WIDTH) * 255).astype(np.uint8)): cov must be in [0, 1]. highShare and type clip after the box average; hires clips before rounding and is written south-up (b8[::-1]).
- export.write_map: master is a 16-bit grayscale PNG (mode I;16, north-up), preview an 8-bit L PNG (north-up), r8gz the gzip of the preview's rows reversed (south-up); only the decoded arrays are frozen (compressed bytes are not an oracle). High share x 254 (255 means none authored); wind PNG is RGB with B = 0.
- bake.box_downsample: f = w // width; f <= 1 returns the input object unchanged (no resample); otherwise crops to (h // f) * f rows and (w // f) * f columns (the output width can differ from `width`: 70 columns to width 16 gives 17) and takes the mean over each f x f block in the input dtype.
- key_seed = zlib.crc32(utf8) & 0x7FFFFFFF (several keys have the top bit set); slug = replace(':', '_').replace(' ', '_').lower() with full Unicode lowercasing (final sigma 'ΑΣ' -> 'ας', 'İ' -> 'i' + U+0307, 'ß' unchanged): Rust to_lowercase matches.
- bake.library_body uses math: edge_at_earth_spin = 30 * sqrt(gh_ratio), period = EARTH_ROTATION_DAYS * center / edge; a center of 0 gives a zero period (hadley 90), a negative one a negative period (edge uses |period|), 5 clamps to HADLEY_MIN 10, 120 to 90.
- fbm: the frequency is cast to float32 (np.float32(f)) before the multiply, the rotation and the offset (uniform 0..256) are float32, q = pts @ rot.T * f + off is a float32 matmul (BLAS summation order and FMA differ) and the position sits near 256 where one float32 ulp is 3e-5: expect 1e-4 noise differences. amp = gain^i, freq = f * lacunarity^i are float64 inputs (plan<i>.amp/freq).
- Perlin3: the permutation is doubled (indices up to 511); the lattice index is np.floor(x).astype(int64) & 255, i.e. a two's-complement mask on negative cells (use rem_euclid(256)); fade 6t^5 - 15t^4 + 10t^3; gradient picked by h & 15.
- Worley3: perm of 1024 doubled (int64), index masks & 1023 with negative cells wrapping, jitter float32 per entry, F1/F2 updated as f2 = where(d2 < f1, f1, min(f2, d2)); f1 = min(f1, d2) over the 27 neighbours; returns sqrt; cell_edges is F2 - F1 at (points @ rot.T) * float32(frequency).
- Flow.backtrace runs in float64 (p.astype(float64), 48 midpoint steps with renormalization) and only the result is cast to float32: the port must back-trace in float64 to meet back's 5e-5; Flow.velocity, ascent and _comma_ascent use each vortex centre from float64 lon/lat (a float32 pole latitude flips the east vector of a cyclone on a pole).
- compose/solve_thresholds/shield run in float64 in Python because the per-row threshold t is a float64 array (s, fine, streak, subtexel are float32 inputs, promoted): the 36-step bisection compares the row mean to the float64 target, lo = -10, hi = 10 (the result is 0.5 (lo + hi), never exactly +-10), and coverage is cast to float32 only at the end.

## metrics_match

## tiles
